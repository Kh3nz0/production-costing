# Phase 3 — Build Plan

Part 6 of 7. Feature-sized outcomes, not coding tasks. Each stage is a thing that works and can be demonstrated. No stage begins before the previous one's "done when" is observably true.

Phase 9 runs these. Nothing here is built before the Figma design and the handoff are approved.

**Sequencing rationale.** S3 before S4 looks wrong until you try it the other way: the ledger's shape is decided by what a receipt needs to record, so building the ledger first produces a ledger that then has to be changed. S6 cannot precede S5 because a cost breakdown with no rates to break down cannot be judged. S10 is deliberately late: a dashboard built before the reports exist becomes a set of numbers with no source.

**What is explicitly not a stage.** There is no "polish" stage and no "make it responsive" stage. Responsive behaviour and every screen state are part of each stage's done-when, because both are the first things dropped when they are scheduled last.
